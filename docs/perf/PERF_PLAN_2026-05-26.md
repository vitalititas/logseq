## Tier 1 — Cross-model consensus (highest confidence to act)

These showed up in ≥2 reports independently. Highest signal-to-noise. Recommend Codex audits these first.

### 1.1 — Search indexer batch + idle budget is absurdly conservative

| Signal | Source |
|---|---|
| `worker/db_core.cljs:74-77` — 8ms time budget + 300ms pause between batches | GLM |
| `worker/db_core.cljs:1104-1153` — batch of 200 with 8ms budget | Devstral |
| `worker/search.cljs:95` — batch size 2000 for FTS insert | GLM, Devstral |

**Synthesis:** the indexer is throttled defensively for low-end devices, but the defaults punish everyone. 8ms with 300ms pause = ~2.6% duty cycle. Bump time budget to 16ms (one frame), pause to 50-100ms, batch sizes upward by ~3-5x. **Risk: low** (worst case = brief jank on weak hardware; can gate on device-perf detection later).
**Impact: large** — directly addresses "graph load is slow" and "search rebuild takes forever" complaints.
**Confidence: high** — three independent agents identified, two different model families.

### 1.2 — Block component over-rendering on long pages

| Signal | Source |
|---|---|
| `components/block.cljs:3952-4450` — `db-mixins/query` subscribes too broadly, full block re-render on any property change | Claude-UI |
| `components/block.cljs:4878-4910` — `block-item` missing `rum/static` → N² cascade | Claude-UI |
| `components/block.cljs:1175-1236` — `page-reference` creates new reactive subs per render | GLM |
| `components/block.cljs:1925-1927, 5000-5010` — progressive render batch size of 1 (root) and 12 (children) too conservative | Devstral |

**Synthesis:** the block render pipeline is the dominant typing-lag source on long pages. Three components stack:
- DataScript subscriptions wider than what's actually rendered (Claude-UI)
- Missing memoization on the leaf component (Claude-UI)
- Page-reference re-instantiating subs on every render (GLM)
- Progressive render hesitating with absurdly small batches (Devstral)

Fix order: add `rum/static` to `block-item` first (lowest risk, biggest win) → narrow `db-mixins/query` subscriptions to actually-used fields → memoize page-reference lookups → bump progressive render batch sizes.
**Risk: low → medium** depending on how aggressive on the DataScript narrowing.
**Confidence: high.**

### 1.3 — DataScript reactivity scope generally too broad

Same theme as 1.2 but broader: across components, subscriptions reactivize on the whole entity rather than the few fields actually rendered. Documented disagreement only on *where* — Claude-UI in `block-container`, GLM in `page-reference`, etc. Likely systemic. After fixing 1.2's specific cases, do a sweep audit of all `db-mixins/query` + `rum/reactive` usages and tighten.

## Tier 2 — Single-model, high-impact findings

These showed up in only one report but are concrete enough to act on directly.

### 2.1 — Source maps + verbose logging shipped in Electron release (Claude-Bundle)
`shadow-cljs.edn:160-163` source maps on, `:40-46, 80-82` `goog.debug.LOGGING_ENABLED true` in release.
**~25MB AppImage reduction**, no behavior change. Pure free win.
**Risk: low. Confidence: high.**

### 2.2 — Lazy-load extension modules (Claude-Bundle)
`shadow-cljs.edn:17-28` — only `code-editor` is split out. Graph visualizer (pixi.js + d3-force ~2MB), pdfjs (~1.5MB), emoji-mart, srs/fsrs, handbooks all bundled with `:main`.
**~25MB additional reduction + 2-4s cold start gain** by extracting these as lazy modules.
**Risk: medium** (extension load order, requires QA).
**Confidence: high** (proven pattern — `shadow.lazy` already used for code-editor).

### 2.3 — db-worker IPC batching (Claude-FileWatcher)
`db/transact.cljs:53-57` — each `apply-outliner-ops` invoke makes a separate IPC round trip. Micro-queue (100ms flush window) collecting consecutive ops into one invoke would coalesce keystroke saves significantly. Devstral hinted at this too (`db_core.cljs:872, 1182, 1298` lacking batching).
**Risk: low** (ops are deterministic, ordering preserved by insertion order).
**Confidence: high.**

### 2.4 — Backup polling at 60-minute interval delays external-change detection (Claude-FileWatcher)
`src/electron/electron/db.cljs:15-16, 60, 134-135` — `backup-interval-ms = 3600000`. External edits (git pull, other-device sync) go undetected up to an hour. Reduce to 60s + add focus/visibility-change refresh trigger.
**Risk: low** (negligible CPU cost increment).
**Confidence: high.**

### 2.5 — Missing `:db/index true` on `:block/refs` (Claude-Indexer)
`deps/db/src/logseq/db/frontend/schema.cljs:71-72` — backlink queries on high-frequency pages (`TODO`, `DONE`) full-scan all refs without inverse index. One-line schema change.
**Risk: low** (DataScript built-in).
**Confidence: med-high** (verify DataScript supports this attribute without re-index cost).

### 2.6 — `:property` query rule self-documented as slow but still in DSL (Claude-Indexer)
`deps/db/src/logseq/db/frontend/rules.cljc:75, 327-345` — rule comment says "slow, don't use" but it's still exported in `db-query-dsl-rules`. Remove from exports, error users toward specific property rules.
**Risk: medium** (breaking change for custom queries — but they were already on slow path).
**Confidence: high.**

### 2.7 — State atom bloat (GLM)
`state.cljs:78-299` — 50+ nested atoms with reactive channels. Migrate rarely-changing state (plugin configs, electron settings) to non-reactive storage; implement state pruning for closed graphs.
**Risk: medium** (touches a core surface; needs comprehensive test).
**Confidence: medium** — needs deeper investigation before patch lands.

### 2.8 — fs.writeFileSync blocking main process (Claude-FileWatcher)
`src/electron/electron/handler.cljs:101-127` — `:writeFile` IPC handler uses sync write, blocking other IPC during parallel writes. Switch to async + per-directory write queue.
**Risk: medium** (atomic per-file semantics must be preserved).
**Confidence: med-high.**

### 2.9 — CSS layout-triggering animation on block insert (Claude-UI)
`components/block.css:1029-1035` — `transition: transform 0.3s ease` on `.ls-block-content-indent` makes block movement feel slow. Disable by default, only enable during drag.
**Risk: low** (CSS-only).
**Confidence: high.**

### 2.10 — Edit handler debounce calibration (Claude-UI)
`handler/editor.cljs:1871-1889` — `edit-box-on-change!` calls `state/set-edit-content!` immediately on every keystroke. Add ~50ms debounce to the state-update side.
**Risk: low.**
**Confidence: medium** (depends on whether `set-edit-content!` is purely sync; verify).

### 2.11 — Virtualization overscan too aggressive (Claude-UI)
`components/block.cljs:4970-4972` — `overscan: 254` renders 256+ extra blocks per scroll tick, each triggering DataScript queries. Reduce to ~100 desktop, ~50 mobile.
**Risk: medium** (need empirical scroll-jank test).
**Confidence: medium.**

## Tier 3 — Architectural / out of scope

These came up but are flagged as not-easy or fundamentally architectural. Not in this round.

- **Recursive ancestor traversal in DataScript** (Claude-Indexer) — DataScript has no transitive closure index; would need SQLite FTS migration to fix structurally. Skip.
- **DataScript memory overhead inherent to in-memory DB** (Devstral, GLM) — fundamental design choice. Skip unless we're switching to pure SQLite backend.
- **Electron Chromium runtime size** (GLM) — can't fix without leaving Electron. Skip.

## Cross-model disagreements (worth flagging)

### Bundle reduction ceiling
- **Claude-Bundle:** 150MB → 75-95MB plausible (50% reduction) with aggressive lazy splitting + source map removal + logging strip.
- **GLM:** "150MB AppImage difficult to reduce significantly" — frames the size as inherent to Electron+Chromium+CLJS toolchain.

**Resolution:** Claude-Bundle is more specific (cites the actual extension modules + asset duplication + source maps). GLM's framing is correct *if you don't touch the lazy-load layer*. Codex should verify Claude-Bundle's lazy-split claim against the existing `shadow.lazy` usage for code-editor — if that works, the 50% number is plausible.

### Backup interval philosophy
- **Claude-FileWatcher:** reduce 1hr → 60s, add focus trigger.
- No other agent touched this.

**Resolution:** safe single-source recommendation. Low risk, observable user benefit. Ship.
